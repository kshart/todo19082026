Запускаем

```bash
sudo docker compose up
```

Идем на http://localhost:8888

# Тестовое задание

Перед выполнением работы пожалуйста внимательно прочитайте все требования. Если какая-то часть не описана, делать на своё усмотрение.

Средствами Nuxt.js 3/4 (Composition API, TypeScript strict) реализуйте небольшое SPAприложение для заметок.

Каждая заметка имеет название и список задач (todo list), далее — Todo. Каждый пункт Todo состоит из чекбокса и относящейся к нему текстовой подписи.

Приложение состоит всего из 2-х страниц.

На главной странице отображается список всех заметок. Для каждой заметки отображается заголовок и Todo, сокращённый до нескольких пунктов, без возможности отмечать. Действия на главной:
 - перейти к созданию новой заметки;
 - перейти к изменению;
 - удалить (необходимо подтверждение).

Страница изменения заметки позволяет заметку отредактировать, отметить пункты Todo, а после сохранить изменения. Действия с заметкой:
 - сохранить изменения;
 - отменить редактирование (необходимо подтверждение);
 - удалить (необходимо подтверждение);
 - отменить внесённое изменение (работает как Ctrl+Z);
 - повторить отменённое изменение (работает как Shift+Ctrl+Z).

Действия с пунктами Todo:
 - добавить;
 - удалить;
 - отредактировать текст;
 - отметить как выполненный.

## Ограничения

 - UI-библиотеки (Vuetify, PrimeVue, Element и т.п.) запрещены; вёрстка и модальные окна — собственные, SCSS/SASS.
 - Библиотеки для undo/redo и автоматической синхронизации стора с хранилищем (pinia-plugin-persistedstate и т.п.) запрещены — синхронизация с хранилищем и история изменений реализуются вручную.

## Семантика истории изменений
 - Непрерывный ввод текста в одно поле — одна запись в истории (фиксация по blur или паузе ввода), а не запись на каждый символ.
 - Отметка чекбокса, добавление и удаление пункта — отдельные атомарные записи.
 - Новое изменение после undo очищает redo-ветку.
 - Лимит истории — 50 шагов; хранение 50 полных копий заметки не допускается.
 - История живёт в рамках сессии редактирования: «сохранить» и «отменить редактирование» её сбрасывают.

## Хранилище
 - Данные переживают перезагрузку страницы; запись — не на каждое изменение.
 - Сохраняемые данные содержат версию схемы.
 - Незасохранённое редактирование переживает случайную перезагрузку страницы: при возврате пользователю предлагается восстановить черновик.

## Edge-cases (обязательны к обработке)
 - Прямой переход по URL несуществующей заметки.
 - Пустое название заметки / пустой текст пункта — осмысленное поведение на ваше усмотрение.
 - Удаление заметки, открытой в этот момент на редактирование во второй вкладке, — приложение не должно ломаться.

## Требования к качеству
 - Unit-тесты (Vitest) на логику истории изменений и стора; компонентные тесты не требуются.
 - Модальные окна: focus-trap, закрытие по Escape, полная работа с клавиатуры.
 - Ctrl+Z / Shift+Ctrl+Z работают глобально на странице редактирования и не конфликтуют с нативным undo внутри текстовых полей.
 - Не использовать алерты — все подтверждения через модальные окна.
 - Переиспользуемые компоненты должны быть вынесены.
 - Адаптивная вёрстка, кросс-браузерность, UI/UX-подходы в дизайне.
 - Работа с менеджером состояния для хранения информации.
